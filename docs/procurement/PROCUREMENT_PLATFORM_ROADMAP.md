# B2B 採購平台 Roadmap

Status: Proposed
Date: 2026-05-15
Scope: Documentation / governance only

本輪為 documentation/governance only。

本文件不涉及 production code、不涉及 DB migration、不涉及 secrets、不涉及 Readdy UI 修改。後續需由 CTO review 後才可進入 implementation phase。

## 1. 產品定位

B2B 採購平台是皇上吉祥跨品類商務基礎，不是單純商品列表，也不是取代業務的自助下單網站。

它的核心目標是把酒、酒機、熟成肉、餐瓷/器皿、調貨商品與未來品類，整理成可治理、可報價、可追蹤、可由業務確認的採購流程。

入口分工：

| Route | 用途 |
| --- | --- |
| `/procurement-admin` | 內部採購管理、商品型錄、價格、報價、訂單草稿、毛利試算、業務歸屬 |
| `/b2b` | 客戶採購入口、專屬商品、專屬價格、常用清單、報價確認、訂單確認 |
| AI LINE Bot | LINE 對話資訊轉換層，將客戶需求轉成採購平台草稿 |

## 2. Phase 1 Scope

Phase 1 應先建立低風險、可人工確認的 B2B 採購骨架。

| 能力 | 說明 | Phase 1 決策 |
| --- | --- | --- |
| 客戶帳號 | 客戶公司、採購人、聯絡方式、可見商品範圍 | 必要 |
| 商品型錄 | 平台可售商品、分類、規格、單位、供應商資訊 | 必要 |
| 客戶專屬價格 | 依客戶、品類、商品、業務條件設定價格 | 必要，但改價需權限 |
| 報價版本 | 每次報價保留版本、有效期限、建立者、確認狀態 | 必要 |
| 訂單草稿 | LINE、業務、客戶入口都先產生 draft | 必要 |
| 業務歸屬 | 客戶、報價、草稿、正式訂單需關聯負責業務 | 必要 |
| 調貨商品 | 不一定在常備庫存內，但可由業務報價與採購 | 必要 |
| 毛利試算 | 成本、售價、折扣、估計毛利 | Phase 1 可做內部試算，不給客戶看 |
| 客戶常用採購清單 | 常購商品、預設數量、週期、備註 | Phase 1 可做簡版 |

## 3. 核心資料概念

本文件只定義概念，不定義 DB schema。

| 概念 | 說明 |
| --- | --- |
| Customer Account | 客戶公司與可登入 `/b2b` 的採購人 |
| Sales Owner | 負責該客戶的業務或團隊 |
| Product Catalog | 可採購商品型錄，跨酒、肉、餐瓷、調貨商品 |
| Customer Price | 客戶專屬價格或價格規則 |
| Quote | 報價單，含版本、有效期限、狀態、負責人 |
| Quote Version | 報價每次調整的不可覆寫紀錄 |
| Order Draft | 尚未正式成立的訂單草稿 |
| Confirmed Order | 客戶與業務確認後才成立的正式訂單 |
| Transfer / Sourcing Item | 調貨商品或需向供應商確認的商品 |
| Favorite Purchase List | 客戶常用採購清單 |

## 4. 報價與訂單狀態

建議狀態流：

```text
inquiry
-> draft_quote
-> quote_sent
-> customer_reviewing
-> sales_reviewing
-> customer_confirmed
-> sales_confirmed
-> confirmed_order
```

治理規則：

1. AI LINE Bot 可以建立 `inquiry` 與 `draft_quote` 的候選內容。
2. 業務可調整報價、毛利、調貨條件。
3. 客戶可在 `/b2b` 或 LINE 端確認需求，但正式訂單仍需業務確認。
4. 正式訂單成立前必須保留報價版本與確認紀錄。
5. 毛利、成本、供應商成本不應暴露給客戶帳號。

## 5. 客戶專屬價格

客戶專屬價格需支援：

| 類型 | 說明 |
| --- | --- |
| 商品固定價 | 特定客戶對特定 SKU 的固定成交價 |
| 品類折扣 | 客戶對某分類套用折扣 |
| 報價限定價 | 僅在特定 quote version 有效 |
| 調貨估價 | 需由業務確認供應、成本、交期 |
| 期間價 | 有生效日與到期日 |

治理原則：

1. 價格調整需有建立者與修改者。
2. 客戶只能看到對其有效的價格。
3. AI 可以建議價格區間或提醒毛利風險，但不可自動改價。
4. 成本與毛利僅限內部角色查看。

## 6. 調貨商品

調貨商品是 B2B 採購平台的重要能力，尤其適用於餐瓷/器皿、特殊酒款、熟成肉特殊規格與一次性需求。

調貨商品流程：

```text
客戶詢問
-> 建立調貨需求
-> 業務/採購確認供應商、成本、交期
-> 建立報價版本
-> 客戶確認
-> 業務確認
-> 正式訂單
```

調貨商品不可直接等同庫存商品，也不可因客戶 LINE 詢問就自動變成正式訂單。

## 7. 客戶常用採購清單

常用採購清單用來降低客戶重複詢價成本。

Phase 1 建議欄位概念：

| 欄位 | 說明 |
| --- | --- |
| 客戶 | 清單歸屬 |
| 商品 | 商品或調貨商品引用 |
| 預設數量 | 客戶常買數量 |
| 單位 | 箱、瓶、組、公斤、件等 |
| 備註 | 客戶偏好、交期、包裝要求 |
| 最近採購 | 供業務參考 |
| 是否啟用 | 可停用過期或不再販售商品 |

## 8. Phase Roadmap

| Phase | 目標 | 內容 |
| --- | --- | --- |
| Phase 0 | 文件與治理 | 本輪文件包、CTO review、source of truth 確認 |
| Phase 1 | 採購骨架 | 客戶帳號、商品型錄、客戶價格、報價版本、訂單草稿、業務歸屬 |
| Phase 2 | LINE Bot 串接 | 客戶 LINE inquiry 轉草稿、業務端確認、客戶確認 |
| Phase 3 | 毛利與調貨成熟化 | 毛利試算、供應商成本、交期、調貨商品 workflow |
| Phase 4 | 跨事業整合 | 酒、熟成肉、餐瓷/器皿、其他商品在同一 B2B 採購入口治理 |
| Phase 5 | 自動化擴充 | 在人工確認門檻下加入 AI 建議補貨、常用清單推薦、報價草稿優化 |

## 9. Implementation Gate

進入 implementation phase 前需確認：

1. `/procurement-admin` 與 `/b2b` 的 route namespace。
2. 客戶帳號與內部業務帳號的權限分離。
3. 報價版本與訂單草稿的 audit trail。
4. AI LINE Bot 只能建立草稿與摘要，不能自動成立正式訂單。
5. DB schema 需另開 migration proposal，不能由本文件直接授權。
